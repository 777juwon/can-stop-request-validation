# 본시험80회 실행 결과 요약

2026-11-01. 사용자가 고정 계획 `runs/main-v1-20261101`의80개 원래 시도를 모두 실행했다. **시도80/COMPLETE80/미시작0, 결과PASS70/FAIL10, 자원 정리PASS80**이다. FAIL10건은 전부 A/T-04의 R-04 STOP_NOT_OBSERVED다. 추가 실행으로 실패를 대체하지 않았다.

이 문서는 실행 완료와 체크포인트 검토 요약이다.2026-11-02에 [전체 분석/그래프/추적표](ANALYSIS_REPORT_2026-11-02.md)와 [최종5장 검토용 원고](THESIS_DRAFT.md)를 작성했다. 본시험 완료를 모든 요구사항PASS나 최종 제출 준비 완료로 표현하지 않는다.

## FAIL인데 실행 완료인 이유

R-04는 동일 순번의 과거 프레임 반복에도 정해진 기한 안에 정지 요청을 해야 한다는 공통 요구사항이다. A/T-04는 슬롯100~159에서99의8바이트 payload 전체가 반복됐고, 배경 순번은 전진했다. A는 매번 거리 프레임을 수신하므로 수신 시각을 계속 갱신했다. 본시험 구간의 정지 요청과 adapter 제동 호출은10회 모두0개였고 차량은 계속 움직였다. 따라서 R-04 FAIL이 맞다.

B는 같은 입력에서 마지막 인정 순번이 갱신되지 않은 시간을 감시해 reason3 요청을 생성했다.10회 모두 W-FAULT 기한, 제어 호출50ms, 실제 정지 창과 복원 뒤 잠금 유지 기준을 만족했다.

COMPLETE는 입력과 기록을 확보해 실행을 끝냈다는 뜻이고, FAIL은 해당 요구사항을 충족하지 못했다는 뜻이다. 이 차이를 비교 결과로 남긴다. A/T-04의 R-06/R-07/R-08은 적용 시작 요청이 없어N/A, 전체증거 R-09는PASS다. 이N/A를0ms 정지나 합격으로 계산하지 않는다.
