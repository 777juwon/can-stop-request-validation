# 메시지 예비시험 8개 결과와 로그 해석

사용자가 preliminary-20261101T093650388216046Z-97982를 실행했다. **8개 모두 COMPLETE, 미시작0개, 요구사항 FAIL은1건**이다. 마지막 COMPLETE_WITH_REQUIREMENT_FAILURES는 중단이 아니라 완료된 시험에 요구사항 미충족이 남았다는 뜻이다. [실제 요약](../evidence/manual/preliminary-20261101T093650388216046Z-97982/summary.json), [추가 원시 대조](../evidence/manual/preliminary-20261101T093650388216046Z-97982/review.json).

## 무엇을 시험했는가

시험 입력 프로그램이 수치 거리와counter를 vcan0로 보낸다. 별도 제어기는 A 또는 B 방식으로 정지 요청을 송신한다. 또 다른 독립 관측기가 입력과 요청의 원시 바이트/시각을 기록한다. 시험기 내부 선언만 믿지 않고 이 관측과 고정 기준을 비교한다. 각조합은 정상 준비 후20초 입력을 실행했다.

A는 유효 거리 프레임이 도착했는지와 거리 조건을 감시한다. B는 여기에 마지막 인정counter의 전진도 감시한다. 같은 거리 값이 계속되더라도 counter가 증가하면 정상일 수 있다. 이번 시험은 거리 값 자체가 같다는 이유로 정지시키는 시험이 아니다.

| 입력 | A의 실제 결과 | B의 실제 결과 |
| --- | --- | --- |
| T-01 정상 원거리와counter증가/회전 | 불필요 정지 요청 없음. R-01/R-05 PASS | 동일 PASS |
| T-02 수치 거리200cm 이하 진입 | 정지 요청. R-02 PASS | 동일 PASS |
| T-03 거리만 중단, 배경 심박 유지 | 수신 만료 정지 요청. R-03 PASS | 동일 PASS |
| T-04 마지막counter/payload 반복 | 정지 요청 없음. **R-04 FAIL** | 순번 갱신 만료 정지 요청. **R-04 PASS** |

T-04의 n100~159는 n99 payload 전체를 반복했다. 원시 로그를 따로 확인해 A는 본 구간에stop=1이 없고 B는reason=3 요청을 냈음을 확인했다. 복원은counter160이었다. A는 계속 도착하는 프레임을 유효 수신으로 보므로 수신 타임아웃만으로 이 조건을 식별하지 못했다. 이것을 시험기 오류로 고쳐 없애지 않고 공통 요구사항 미충족으로 보존한다. B가 모든 형태의 오래된 측정값을 검출한다는 뜻은 아니다.

## 각 필드의 의미

- execution_status=COMPLETE: 해당 입력과 기록을 확보해 판정할 수 있게 실행을 마쳤다. 모든 요구사항PASS라는 뜻은 아니다.
- requirements의 R-xx: 고정 명세에 정의된 개별 요구사항이다. PASS/FAIL은 해당 범위의 만족/미충족이다.
- WITHIN_WINDOW: 정지 요청의 독립 관측 시각과 원인이 정해진 창을 만족했다.
- STOP_NOT_OBSERVED: 본 구간에 필요한 정지 요청을 독립 관측하지 못했다.
- R-08 PASS: 이번 메시지 예비 단계에서는 정지 이후 입력 복원에도 요청을 유지하는 부분을 확인했다. CARLA 제동 유지까지 확인했다는 뜻은 아니다.
- N/A/CARLA_NOT_EXECUTED: 이번 실행에 차량 제어 호출/차량 운동 검사는 포함하지 않았다. R-06/R-07은 미수행이다.
- R-09 N/A, message_evidence_valid=true: 메시지 수준 근거는 확보했으나 차량을 포함한 전체증거 요구사항은 아직 미수행이다.
- main_trials_executed=0: 이8개는 예비시험이며 본시험80회에 포함하지 않는다.

## 실제 관측 지연

아래는 입력의 실제 송신 완료부터 독립 관측기의 요청 관측까지 같은호스트 monotonic 시각으로 계산한 값이다. 차량 정지시간이나 물리CAN 전송 지연이 아니다. 한 번씩의 관측이며 본시험 반복 통계가 아니다.

추가 검토에서8개 모두 evidence_valid=true, evidence_errors/missing_evidence/sut_output_errors/cleanup_errors 빈목록을 확인했다. 입력+요청 원시 프레임 다중집합과 독립 관측이 전부 일치했고 각 실행의9개 소스SHA도 검토 당시 파일과 일치했다. 이는 기존 전체oracle를 새로 실행한 것과 구분되는 별도 대조다. 이후 본시험 준비에서 G4 실행기를 확장했으므로 당시 실행 소스는 기록된e6f0a5f 커밋을 기준으로 확인한다.

원시 JSONL24개 약14.3MB는 이 로컬 폴더에 보존하고 Git 게시에서는 제외한다. 요약/판정/metadata와 [원시 파일 크기/SHA 목록](../evidence/manual/preliminary-20261101T093650388216046Z-97982/raw_manifest.json)을 관리한다. 원시 자료 없이 요약만 받은 환경에서 전체 재판정을 수행했다고 주장하지 않는다.

242개 단위 검사는 가짜 시각/대역/고정 바이트 등 코드 검증이다. 이번8개는 실제vCAN의 독립 프로세스 간 메시지 통합 예비시험이다. 다음은 CARLA 본시험 실행기와 고정 설정/80개 원래run ID를 준비하는 단계이며 현재 본시험0/80회다. 초기 INPUT_ERROR 시도도 이전 폴더에 보존한다.
